# 随 App 更新的控扇服务（0.4.6）

只安装一个 AgenticFan.app。普通用户进程负责界面、CLI、曲线求值和 Hook；内置系统服务仅执行受限硬件操作。监测温度不需要授权。首次启用控扇时，在 App 中选择“授权控扇”，按 macOS 提示允许后台服务。全新安装还需要管理员批准将控扇权限授予当前本机账户。CLI 的显式调速也能发起同一流程；无需另装 Helper.app。

## 安装与升级

系统使用 [SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice) 注册 App 包内的 LaunchDaemon；plist 位于 `Contents/Library/LaunchDaemons`，用 `BundleProgram` 引用同包的原生入口。Apple 要求包含 LaunchDaemon 的 App 公证；开发 DMG 用于模拟与隔离测试，不视为已获真实授权。需要登录前即可找到 App 时建议使用 `/Applications`。

- 升级前结束会话并退出旧 App。安装器默认放在用户 Applications；已有全局安装时原位更新。保留规则、曲线、Hook、旧 App 和既有授权账户。显式 `--user-root` 隔离安装不操作系统服务。
- 已授权的服务在替换前停止接受新写入；如有活动会话则拒绝更新。等待系统注销完成后，随新 App 重新注册。App 启动也检查运行中的服务是否来自当前包；不需要用户单独升级后台二进制。协议兼容按 IPC 版本判断，不再比较整个 UI/CLI 构建的哈希。系统要求批准时显示“等待批准”，不能算作控扇已就绪。
- 0.4.5 迁移沿用原 root 所有的账户授权记录。新服务获准且原会话锁空闲后才退出已识别的旧 launchd 作业；旧定义移到受保护的备份位置，旧运行时保留作回退，不再执行或更新。忙、所有者不符、定义不匹配时拒绝接管；归档失败会尝试恢复旧作业。系统设置中禁用的服务不循环重注册。
- 回退版本：先结束控制、恢复自动模式，在新版中注销服务，再使用保留的旧签名 App/安装器；旧版如需控扇，按旧版流程重新授权。不要同时启用两代服务。卸载时在删除 App 之前运行 `agenticfan helper uninstall`。如需一并撤销本机账户绑定，请在服务仍获准运行时执行；已在系统设置禁用的服务无法清除原绑定。
- `helper status` 只读；`helper install` 是显式启用入口，`helper reconcile` 仅协调已选择的服务。查看 `state`、`running`、`compatible` 及 `ready`：授权待处理或迁移未完成时，即使 App 安装成功也不能声明可控扇。

## 权限与停止行为

原生服务入口仅从相邻文件读取构建时固定摘要的工作程序，在 root 专有运行目录中校验实际复制的字节再原子提交。独立 guardian 只从该受保护路径运行，使用固定参数和清理后的环境。无需复制整份 App，亦不从用户可写目录加载 Python、插件或 Hook 作为 root 执行。

客户端验证 socket 目录及对端 root 身份；服务通过内核 peer UID 验证请求。未绑定账户时仅允许查询和经 Authorization Services 验证的管理员授权绑定；不接受客户端指定 UID，不记录授权凭据。已绑定时 socket 仅供授权账户访问。授权属于本机账户，不能据此判断某个 App 的身份。硬件操作限于有范围及期限的 set、已选风扇的 RPM 更新和 auto，不接受任意键、命令、路径或环境变量；管理操作另行校验。不会更改 sudoers 或关闭系统安全。

会话仍有独立锁、租约与恢复守护。手动 `fans set` 保持 1–3600 秒硬期限，目标更新不延长它；读回过程中到达这个期限按正常到期恢复自动，不再记成转速未确认。应用内的曲线和阈值规则只有 5 秒心跳租约，没有墙钟期限：应用还在、采样新鲜时持续握着风扇。模式/目标写入需读回；断开、停止、失联经过同一恢复路径。0.4.6 将读回期间的取消带入恢复流程，记录原因。已知采样过期、租约到期或观察中断，只有恢复自动已核实且再次取得连续两次新鲜有效采样、风扇仍为 auto 时才重启控制。明确外部 auto、另一控制者、未知取消、真正硬件错误和未确认恢复不自动重试。运行态可查看 `last_interruption` 和 `pause_code`。guardian 或内核失效、其他控制器竞争等仍可能妨碍恢复。控制线协议为 3。
