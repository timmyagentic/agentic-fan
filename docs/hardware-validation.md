# Apple Silicon 硬件验收

当前仅有下面列出的机型与场景通过实测。Linux 的模拟测试与 macOS CI 只验证软件路径，不能从一台机器外推到所有 M 系列。

已有一次用户安装与只读反馈：可发现 255 个温度测点及风扇接口；两个 IOHID PMU 测点约 −9200°C，20 个零值待确认，1 个不可用；部分未映射的 SMC 键约 115.6°C。系统事件中也有异常 PMU 数值，未发现正常温度被 MacFan 解码成该值的证据。机型、macOS 和应用构建号未在该反馈中给出，不能填入兼容性通过记录。此次没有执行真实调速或自动恢复测试，属于尚未验收而非已发现的控扇故障。0.2.0 的软件修复及复查见 [温度有效性说明](temperature-validation.md)。

## 只读验收

在真实 Mac 安装后，以普通用户运行 `macfan capabilities`、`macfan sensors` 和 `macfan fans`。记录输出中的机型、架构、系统版本、传感器来源、数量、错误，以及每把风扇的范围。不要收集序列号或许可证。

确认 AppleSMC 能连接，IOHID 不可用时警告明确。初代 M1 应特别核对 CPU/GPU 测点是否来自 IOHID。用可信的现有读数比较几个代表性测点，记录原始键与位置的映射依据。风扇列表应和设备一致；无风扇 MacBook Air 返回空列表属于正常结果。

运行 `macfan watch --interval 1 --count 30`，确认时间推进、温度变化、错误值不会被替换成旧读数。记录失败或不可用项，不用虚拟测试代替。

运行 `doctor` 核对 `sensor_summary` 的分类和来源统计。检查 PMU 异常是否保留原始值、排除出可用值并产生警告；零值和缺失值不能计入 `valid_sensor_count`。高温键须保留原值和未确认的物理映射，不能仅凭通过范围检查认定散热正常。

## 有限控扇验收

先退出其他控扇程序，并确认风扇处于自动模式。使用 `fans` 给出的范围，首次选一个高于当前转速、低于或等于最大转速的目标值，安装 Helper 后以普通用户运行不超过 15 秒的会话。不要把示例 RPM 当作所有机型通用的值。

检查 `control_started`、实际 `control_confirmed` 和 `control_finished`。结束后用独立的 `fans` 调用复查自动模式。若只有写入成功而没有实际转速响应，记为失败，保留结构化错误。

随后检查 Ctrl-C、另一终端 `fans auto --fan all`、以及仅终止 CLI 父进程时的恢复。父进程终止测试不得同时终止 `control_started` 中给出的 `guardian_pid`。这些测试必须有独立的模式复查，不能仅依赖进程退出。

对于双风扇机型，记录单扇操作是否影响另一把风扇。若硬件存在耦合，应停止单扇兼容性声明，另行定义该机型的控制组。

## 实验路径和限制

只有普通路径明确不支持、且具备恢复手段时，再单独评估 `--experimental-ftst`。记录上层/小写模式键、Ftst 初值、目标写入结果、实际响应延迟与恢复后的键值。尚无通用兼容承诺。

睡眠前恢复尚未实现系统通知挂钩。当前只能在恢复运行后检测观测间隔异常并结束控制。验收此行为时应单独记录睡眠期间的实际风扇表现，不得将其标为已具备睡眠前保护。

## 0.3.0 实测记录（2026-10-16，Asia/Shanghai）

测试 App 为本机 arm64 构建，内置可执行文件 SHA-256：`251c12a0eda4f2313af6123abec1520b333b604d4c0a26e8af331128474f0a47`。源代码提交 `e71eda4c9cf495c6388143fd813f92049d52c217`；后续提交仅补充本记录与 README。

- 一次系统管理员授权安装 Helper；服务运行于 root 所有的独立 App 副本。此后以下操作全部以普通本机用户运行，没有 sudo 或再次授权。
- 重复 `helper install` 返回运行中/兼容，未启动授权流程。
- 1 把风扇，1000–4900 RPM；`F0Md` 存在，`F0md`、`FS! `、`Ftst` 不存在。
- 214 个温度测点：199 个通过合理性检查，15 个零值待确认。不是物理位置或温度校准证明。
- `fans set --fan 0 --rpm 1600 --duration 15`：收到目标写入、实际 RPM 进入容差、到期自动恢复三个事件，退出码0。期间独立读取实际1601 RPM、目标1600、manual；结束后独立读取actual1001、target1000、auto。
- 第二次相同会话期间调用 `fans auto --fan all`：恢复命令与原会话均退出0，原会话结束原因为external_auto。独立查询确认auto。
- 第三次会话确认转速响应后，仅SIGKILL普通CLI：Helper/guardian仍执行恢复，独立查询确认auto。随后实际与目标均为1000 RPM。
- 新版窗口可正常显示真实温度和系统自动模式，明确首次安装Helper的授权行为。

未验证：其他机型、Helper或guardian被强制终止的实机恢复、睡眠前保护、长时热负载、Ftst、Gatekeeper在干净机器的放行与Apple公证。不能把短时控扇通过当作整机热安全保证。
